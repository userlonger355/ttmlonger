# Migration audit — requested original MargyT behavior
Source inspected directly: user archive MargyT-main (2).zip, LICENSE and ADDITIONAL-TERMS.md, README.md, SettingsActivity.java, SettingsRow.java, UiStyle.java, Design.java, Feed.java, Dates.java, NativeRead.java, Comments.java, TabBadges.java, TabCount.java, plugin/MargyPlugin.java, and margyt/dexpatch.py.
Current TTMLonger is an LSPatch module. MargyT is a build-time DEX patch project. Its date feature uses TWO hooks: VideoAuthorInfoRelationAssem.onViewCreated/s4 and VideoDescAssem.a2(int,Aweme), selected by the string "onHolderSelected: awemeId="; current TTMLonger does not implement the exact selected callback. Original dates depend on DateOverlay, DateInfo, VideoActions, NativeRead and generated native anchors. Feed includes direct iget redirection, not just getter hooks. Plugins may depend on private MargyT classes; public API parity does not guarantee a working Motion Blur plugin. Original SettingsActivity uses Skin, Design, SettingsCell, UiStyle and resources. Replacing one class at a time with guessed code is not a faithful port.
A faithful migration should use the original patcher and retain original implementation, tests, resources and dependencies, with the exact base version verified before changing version-specific anchors. The archive states GPL-3.0 plus section 7 terms: retain the original author section at the same prominence, source/support links and modified-build notice; do not adopt the MargyT name/icon; modified source remains under the same license. The existing TTMLonger license has not been established. No original source was newly incorporated in this commit, and no project-wide relicensing was performed without confirmation. This commit only removes tinted settings surfaces and places the TTMLonger author next to version. It does not claim any new original-function port.

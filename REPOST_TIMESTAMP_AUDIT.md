# Repost timestamp and settings branding
Expanded the native event reader: dedicated UpvoteInfo/RepostInfo records need not provide a numeric upvote ID to expose a real timestamp; explicit mismatched item IDs and conflicting times are rejected. Direct upvote/repost event fields are supported; generic creation time is read only from the dedicated event record. Never derive a timestamp from an ID or substitute publication time. Display full date/time with seconds. Added two runtime fixtures. The supplied MargyT archive RepostPurge.java confirms native UpvoteInfo linkage but does not establish an exact timestamp field in TikTok 47.9.3. Real repost data is still required to validate. Removed marketing mentions in TTMLonger settings, preserved plugin manifest authors, API binary names, third-party service disclosure, source attribution and legal notices.
